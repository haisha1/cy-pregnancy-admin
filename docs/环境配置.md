# 环境与数据库连接切换

## 三种模式

| profile | 使用场景 | 数据源 | Flyway | 接口文档 | 初始账号 |
| --- | --- | --- | --- | --- | --- |
| local | 本地开发 | 默认 127.0.0.1:3306 / 6379 | 正常迁移开发库 | 开启 | 仅空开发库创建 |
| remote | 本地 Java 连接线上依赖 | SSH 转发后的 23306 / 26379 | 关闭 | 关闭 | 不创建 |
| prod | Jenkins Docker 部署 | Docker 网络 mysql:3306 / redis:6379 | 正常执行发布迁移 | 关闭 | 仅通过显式配置开启 |

remote 服务只监听 127.0.0.1。关闭迁移不代表只读：业务接口仍可能写线上数据；仅使用明确授权的测试账号和业务操作，运行前备份。自动化测试禁止使用 remote。

## 本机 MySQL / Redis

在 Maven 工程目录复制模板：

~~~powershell
New-Item -ItemType Directory -Force .local | Out-Null
Copy-Item config/connections-local.properties.example .local/connections-local.properties
powershell -ExecutionPolicy Bypass -File scripts/dev.ps1 -Task run -Connection local
~~~

已有文件不要覆盖；编辑 .local/connections-local.properties 后重启。模板的 root/root 只适用于现有本机开发环境，按实际环境修改。字段前缀为 ADMIN_，数据库名 cy_pregnancy_admin。MySQL 和 Redis 的地址分别填写，可以按需要只切换其中一个依赖。

## 连接服务器数据库和 Redis

服务器 MySQL Compose 需已有 ports: ["127.0.0.1:13306:3306"]；Redis 若需要从电脑调试，给 redis 服务添加 ports: ["127.0.0.1:16379:6379"]，应用配置与密码不变。在服务器基础设施目录校验 Compose 并更新对应服务，更新会有短暂连接中断。不要开放公网数据库端口，不执行 down -v。

在电脑另开 PowerShell，建立隧道并保持窗口运行：

~~~powershell
ssh -N -L 127.0.0.1:23306:127.0.0.1:13306 -L 127.0.0.1:26379:127.0.0.1:16379 root@106.52.111.175
~~~

SSH 不是 22 端口时增加 -p 实际端口。端口冲突时修改左侧本机端口，并同步连接配置。

~~~powershell
Set-Location D:/code/cy-pregnancy/cy-pregnancy-admin/server
New-Item -ItemType Directory -Force .local | Out-Null
Copy-Item config/connections-remote.properties.example .local/connections-remote.properties
~~~

只在首次复制；填写 ADMIN_DB_PASSWORD、ADMIN_REDIS_PASSWORD 和实际业务账号，不复制 MySQL root 密码。然后启动：

~~~powershell
powershell -ExecutionPolicy Bypass -File scripts/dev.ps1 -Task run -Connection remote
~~~

IDEA 同样可以设置 SPRING_PROFILES_ACTIVE=local 或 remote，工作目录设为 Maven 工程目录。已有环境变量优先于文件，切换时检查旧的 DB_* / ADMIN_DB_* / REDIS_* 环境变量。配置中使用的是本机隧道地址，不能填写 Docker 内部的 mysql、redis 作为电脑可解析地址。

## 凭据和服务间调用

prepare-local.ps1 只生成或复用本机密钥，不覆盖 connections-local.properties / connections-remote.properties。local 和 remote 可以读取忽略目录的本机密钥；prod 只从 Jenkins 凭据注入，不导入这些本地文件。若 remote 要调用线上另一个 Java 服务，还需在远程连接文件填写对应 ADMIN_READ_KEY、CONTENT_READ_KEY 及服务地址；本机生成密钥不会自动匹配生产。只调试本机两个 Java 服务时，继续使用本机默认互调地址。

管理 JWT 与用户 JWT 必须独立。远程 profile 禁止 bootstrap，不会生成或重置线上管理员。所有真实配置不提交 Git、不写进 classpath、不打印到日志。
