# 管理接口与业务流程

API前缀`/admin/api/v1`，JSON/HTTPS（本机开发用HTTP）。运行时OpenAPI位于本地`/v3/api-docs`，可导入Apifox；接口以当前 Controller、DTO 和本地运行时 OpenAPI 为准，不保留易过期的导出快照。

统一响应`code/message/data/requestId/serverTime`；无权限403、未登录/过期401、字段不合法400/422、资源不存在404、并发/幂等/状态冲突409、缺If-Match为428、限流429、依赖故障503。错误响应不包含密码、token、SQL和内容全文。

## 权限矩阵

| 角色 | 权限 |
|---|---|
| security_admin | operator:read、operator:manage、audit:read、user:read、dashboard:read |
| content_editor | knowledge:read、knowledge:edit、dashboard:read |
| clinical_reviewer | knowledge:read、knowledge:review、dashboard:read |
| publisher | knowledge:read、knowledge:publish、dashboard:read |

角色为数据库迁移预置，只读API返回清单；当前不提供随意编辑权限码的角色CRUD。安全管理员可给一个账号多个角色，但代码仍禁止作者自审。实际审核人员、资格和责任由组织明确，给角色不等于完成临床认证。

## 接口目录

| 方法/路径 | 权限/行为 |
|---|---|
| POST /auth/login | 公开密码登录；Redis按连接地址和账号分别限流 |
| GET /me | 登录即可；当前账号和最新权限 |
| POST /auth/logout | 登录即可；撤销当前会话，无body |
| POST /auth/password | 登录即可；旧密码+新密码，If-Match使用账号revision |
| GET /operators | operator:read，beforeId/limit分页 |
| GET /roles | operator:read，预置角色/权限 |
| POST /operators | operator:manage，创建账号及角色 |
| PATCH /operators/{uuid} | operator:manage，改显示名/状态/角色，If-Match为账号revision |
| POST /operators/{uuid}/password | operator:manage，重置密码并撤销目标会话 |
| GET /knowledge | knowledge:read，条目及最新版本摘要 |
| GET /knowledge/{articleUuid}/versions | knowledge:read，该条目版本摘要分页 |
| GET /knowledge/versions/{uuid} | knowledge:read，完整双表达、来源、审核、版本信息 |
| POST /knowledge | knowledge:edit，原子建立条目及第一份草稿 |
| POST /knowledge/{articleUuid}/versions | knowledge:edit，新版本；If-Match是条目revision |
| PATCH /knowledge/versions/{uuid} | knowledge:edit，仅作者可改draft |
| POST /knowledge/versions/{uuid}/submit | knowledge:edit，仅作者draft可送审 |
| POST /knowledge/versions/{uuid}/review | knowledge:review，submitted可审核，禁止自审 |
| POST /knowledge/versions/{uuid}/publish | knowledge:publish，仅approved可发布 |
| POST /knowledge/{articleUuid}/withdraw | knowledge:publish，下架当前发布版本；If-Match是条目revision |
| GET /audits | audit:read，只读最小审计元数据 |
| GET /capabilities | 登录即可；如实返回当前已实现/未实现能力 |
| GET /operators/{uuid} | operator:read，管理员详情 |
| GET /knowledge/review-queue | knowledge:review，服务端审核队列 |
| GET /knowledge/release-queue | knowledge:publish，待发布或当前发布队列 |
| GET /dashboard/summary | dashboard:read，按当前角色返回摘要 |
| GET /dashboard/user-trend | user:read，1–30 天匿名用户统计 |
| GET /dashboard/recent-activity | audit:read，最近活动 |
| GET /users、GET /users/{uuid} | user:read，最小匿名用户查询 |
| GET /system/health | operator:read，依赖探测，不暴露连接凭据 |

内部 /internal/content/knowledge 由用户服务使用独立 CONTENT_READ_KEY 访问，不经公网代理。

除登录和退出外，写接口要求`Idempotency-Key: <小写UUID v4>`；创建资源时body的UUID同样保持稳定。更新/状态变化还需`If-Match: "1"`等带双引号版本。前端修改载荷或开始新动作时换新的操作UUID；请求超时后原动作复用key恢复原回执。登录/退出不走写命令回执，密码变更撤销当前会话后须重新登录。

分页为beforeId/limit，默认20最大100，按内部ID降序；下一页使用返回nextBeforeId，为null结束。没有使用offset分页，也没有提供未实现的搜索过滤参数。

## 账号示例

```json
{
  "clientUuid": "7df0ce57-04f7-4af6-9f11-6d3dc0cad235",
  "username": "content_editor_one",
  "displayName": "内容编辑",
  "password": "<YOUR_RANDOM_PASSWORD>",
  "roleCodes": ["content_editor"]
}
```

使用安全管理员token提交POST /operators。示例密码只是字段说明，请替换为本机生成的真实密码，不把凭据粘贴到工单/版本库。修改账号需要完整displayName/state/roleCodes，state为active/disabled；修改后目标账号全部会话撤销。

## 内容闭环

1. 安全管理员创建独立编辑、审核和发布账号，分别给预置角色；不要默认给一个账号全部权限。
2. 编辑账号POST /knowledge，创建条目UUID和版本UUID。编辑阶段内容可调整，references允许暂为空；evidenceNote始终必填。
3. POST版本/submit，If-Match使用版本当前revision；无引用422。送审后禁止编辑原版。
4. 另一个审核账号POST版本/review，body=`{"decision":"approve","note":"审核说明"}`或reject。自审403，即使作者被授予审核权限也不允许。
5. 发布账号POST版本/publish，If-Match使用审核后的版本revision；未批准409。重复同key返回原回执，不重复发布/审计。
6. 创建新版本使用条目当前articleRevision（详情/摘要都返回），填写完整新内容，旧发布内容继续保持。新稿经审核和发布后才切换指针。
7. 下架使用条目revision，清空当前发布指针并将目标版本标withdrawn；下架不是删除历史，也不能宣称已从小程序缓存撤回，因为当前没有内容分发链路。

创建知识示例（结构演示，不是批准的医学内容）：

```json
{
  "clientUuid": "683dd6db-5842-4894-8e40-cf218763ae16",
  "versionUuid": "d72140dd-a97e-455f-b5fa-d3c5d6db02a2",
  "slug": "term-example",
  "title": "待编审的术语说明",
  "category": "术语",
  "proContent": "专业表达草稿，需审核",
  "plainContent": "对应的白话表达草稿，需审核",
  "references": ["真实来源的完整引用，实际录入时替换"],
  "evidenceNote": "编写和审核依据，实际录入时替换"
}
```

正文为纯文本契约；管理网页展示时做文本转义，不能直接innerHTML。reference字符串目前只登记引用，不自动验证版权、原文真实性或医学正确性；这些需审核人员完成，模型数据包发布另行实现。

## 最小回执与版本

写操作返回`uuid/revision/state/parentUuid`，不返回密码、全文或实体。知识版本写入时uuid/revision属于版本，parentUuid是条目；新增/下架条目要先从GET详情/摘要读取articleRevision。同一个幂等key重放返回最初回执，即使后来资源版本已前进；它不是最新详情查询。

只有成功命令消耗幂等key。缓存回执保存到独立表，状态/版本检查在幂等恢复之后进行；服务端会先复核当前权限和会话，撤销授权后不能用旧key绕过鉴权。
