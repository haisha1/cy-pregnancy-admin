# 分层与代码阅读指南

本工程优先让Java基础较少的开发者能沿调用链定位代码。分层和接口沿用用户端要求，管理业务采用独立根包`com.chunyu.pregnancy.admin`，不会扫描用户端组件。

## 每一层做什么

| 层 | 示例 | 职责 |
|---|---|---|
| controller | KnowledgeController | 接收/校验HTTP参数、声明权限、调用Service、统一返回 |
| dto/request | CreateArticleRequest、ReviewRequest | 允许客户端提交的字段与输入限制，不含操作者ID |
| dto/response | KnowledgeResponse、MutationResponse | 公开返回字段，不泄漏密码散列或原始Entity |
| service | KnowledgeService、AdminOperatorService | 定义可用业务行为和接口契约 |
| service/impl | KnowledgeServiceImpl | 判断状态、权限/归属、版本冲突及业务副作用 |
| service/support | CommandExecutor、AuditWriter | 共用的业务事务执行和最小审计；会访问Mapper，因此放Service而非common |
| mapper | KnowledgeVersionMapper、AdminAccessMapper | 通用CRUD和角色关联/锁定等显式SQL |
| entity | KnowledgeVersion、AdminOperator | 与数据表一一对应，只用于持久化 |
| security | AdminSessionFilter、AdminTokenService | 认证凭据及会话/实时权限装配 |
| config | AdminSecurityConfig、AdminBootstrap | 装配组件、绑定配置、首次空库初始化 |
| common | ApiResponse、BizException、RevisionHeaders | 跨模块基础工具，不放具体业务SQL |

## 登录调用链

1. RequestIdFilter生成requestId，后续成功/失败响应都可用于排查，未启用请求体日志。
2. AdminAuthController先用Redis限流，再调用AdminAuthService接口。已有账号和不存在账号都执行BCrypt校验，错误信息一致。
3. AdminAuthServiceImpl在事务外校验散列，然后在写锁内再次校验账号状态和密码是否已变化。
4. 同一事务创建会话、记录成功登录事件，再签发JWT；事务失败不返回有效登录结果。
5. 后续请求先验证签名、issuer、audience和kind，再由AdminSessionFilter → AdminSessionService查MySQL权威会话及最新权限。
6. Controller的`@PreAuthorize`检查具体权限；管理写命令持锁后再次检查会话、账号状态及权限，避免排队期间被撤销后继续写。

JWT不保存角色清单。禁用账号、改角色或重置密码会撤销会话；退出只撤销当前会话。管理JWT和小程序JWT使用独立配置、issuer/audience/kind，两边凭据不能通用。

## 知识命令调用链

`KnowledgeController → KnowledgeService接口 → KnowledgeServiceImpl → CommandExecutor → Mapper → MySQL`。

CommandExecutor使用TransactionTemplate明确事务边界，在数据库中锁admin_write_lock固定行。写入量小时串行化管理命令，有助于同时保证幂等和跨资源规则；锁在多个Docker实例间也生效。后续要按资源拆锁时必须连同最后一名管理员、发布指针和幂等竞争一起重新设计，不能只删锁提速。

锁内先验证当前权限，再查幂等回执。相同actor+命令+operationUuid、相同规范化载荷返回原回执；载荷变更报409。成功命令才写回执；失败会连同业务、审计一起回滚。回执只含UUID/状态/版本，输入只存HMAC摘要，不复制密码或内容正文。

内容状态判断以MySQL值为准；If-Match版本避免用户看到旧页面后覆盖别人操作。作者可编辑自己的draft，一旦送审便不再改写正文。拒绝或发布后要重新创建完整草稿，原审核和内容保留。

## 关键实现细节

- 发布需approved且存在非作者的审核者；发布事务同时更新版本状态和条目发布指针。数据库里标published仅代表管理流程发布，不表示已取得临床资质或已分发小程序。
- 下架要把published_version_id明确设NULL。MyBatis-Plus默认忽略实体里的null，因此使用LambdaUpdateWrapper显式清空；测试检查真实数据库指针。
- 最后一名可用security_admin不能被禁用或移除角色。该检查和更新在同一写锁内，不能先查数量再在另一个事务更新。
- Entity未用`@Data`生成默认toString，防止误输出密码散列。Lombok只生成Getter/Setter；主业务分支和事务仍是显式Java。
- BCrypt上限按UTF-8字节验证，不能把72个中文字符当72字节。重置/改密只返回最小回执，不回显密码。
- 列表只读版本摘要字段，详情才加载双表达正文，避免每页100条携带大量内容。

## 新模块怎样添加

先定义独立Request/Response和Service接口，再实现ServiceImpl、Entity、Mapper及Flyway新迁移。Controller保持薄，不拼SQL、不直接返回Entity。业务状态、归属、权限和并发规则写在Service及必要注释中；不要逐行翻译简单赋值。每个真正开放的能力通过负向权限和失败恢复验证后再改capabilities。
