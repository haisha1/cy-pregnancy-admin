# 部署与后续事项

## 本机与云端分开

本机默认local，使用用户提供的root/root和无密码Redis，仅开发使用。prod通过ADMIN_DB_*、ADMIN_REDIS_*、ADMIN_JWT_SECRET配置，不使用用户端JWT_SECRET。管理服务端口18732，Docker内数据库服务名admin-mysql，Redis服务名admin-redis，不能用容器localhost连接另一个容器。

同目录的Dockerfile、compose.yml和deploy/nginx.conf.example是部署模板。本机没有Docker，因此未做镜像构建、Compose运行或腾讯云实际部署验证。

## 腾讯云轻量部署顺序

1. 复制server目录，排除target、.local、.env和日志；在服务器安装Docker/Compose。
2. 复制.env.example为.env，配置独立数据库、Redis密码及至少32字节随机ADMIN_JWT_SECRET，不复用小程序端密钥。
3. 首次空库部署需要临时设ADMIN_BOOTSTRAP_ENABLED=true和强随机ADMIN_BOOTSTRAP_PASSWORD；创建初始安全管理员后关闭开关并移除该密码。重启不会覆盖已有账号。
4. 执行`docker compose config --quiet`再执行`docker compose up -d --build`；检查api日志与`curl -f http://127.0.0.1:18732/actuator/health`。
5. 通过HTTPS、VPN或IP白名单提供管理入口。示例Nginx默认只允许127.0.0.1，需按真实运维来源配置；数据库/Redis不发布公网端口。
6. 使用初始安全管理员创建实际编辑/审核/发布账号，关闭bootstrap；按接口文档进行独立审核闭环。正式审核责任人需另外明确。

Compose有独立MySQL volume；不要执行`down -v`误删数据。若服务器已有MySQL/Redis，可使用现有私有网络资源和独立数据库账号，不必重复创建实例。发版前备份并验证恢复；Java升级回退和数据库DDL回滚是两件事，不能假设回退镜像能撤回DDL。

## 生产前明确事项

- Java 8/Boot 2.7已结束公开维护的依赖风险需要落实维护或升级方案；本轮按用户指定环境开发，不自动升级本机。
- MFA/企业身份源未实现，当前只适合受控内网联调；公开生产管理入口前明确MFA及密码重置流程、人员角色与审批责任。
- 当前限流按连接IP和用户名计数。代理后需配置边缘限流及仅信任指定代理的来源解析，不直接相信任意X-Forwarded-For；账号维度限流持续生效。
- 增加过期会话清理、审计/幂等保留策略、失败登录监控、备份及密钥轮换。当前HMAC比较与JWT共用管理密钥，需用途分离/版本化迁移后再滚动换密钥。
- prod关闭Swagger/OpenAPI，应用只暴露健康状态；禁止开启请求体/凭据/内容正文日志。
- 当前发布内容经用户服务按需读取且不缓存正文，下架后重新读取返回404；不会远程抹除用户已经看到的信息。

## 后续模块

| 模块 | 尚需输入和实现 |
|---|---|
| 管理网页 | 已实现Vue3/TS/Vite，回归与范围见根docs/INTEGRATION.md |
| 用户端内容分发 | 已实现独立密钥、当前版本只读、下架404；历史发布回滚仍待实现 |
| 模型/参考包 | 注册函数ID白名单、单位/范围、原文/授权证据、核验向量、批准与版本兼容 |
| 发布回滚 | 历史发布记录、目标批准状态、兼容性/撤稿限制及原子切换；当前不提供回滚接口 |
| 反馈/任务/删除监管 | 先由用户端实现真实资源/任务，再设计只读/受控重试API和最小权限 |
| 动态角色管理 | 权限目录、角色编辑审批及最小权限约束；当前只有预置角色和账号角色分配 |

长远需求继续参照`cy-pregnancy-admin/docs/管理后台后续开发设计.md`。本轮不创建假工单、假任务或可任意修改临床阈值的接口。
